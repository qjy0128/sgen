# 领域文档

工程技能在探索本代码库时，按以下规则消费领域文档。

## 探索前先读

- 仓库根目录的 **`CONTEXT.md`**；若存在 **`CONTEXT-MAP.md`** 则按其指向读取各上下文的 `CONTEXT.md`
- **`docs/adr/`**：阅读与当前工作区域相关的 ADR

以上文件若不存在，**静默继续**：不提示缺失、不建议预先创建。`/domain-modeling`（经 `/grill-with-docs`、`/improve-codebase-architecture` 触达）会在术语或决策真正落定时惰性创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── ...
└── src/
```

## 使用词汇表术语

输出中命名领域概念（工单标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 定义的术语，不用词汇表明确回避的同义词。

若所需概念不在词汇表中，这是一个信号：要么你在发明项目不用的语言（请重新考虑），要么存在真实缺口（记下来留给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与既有 ADR 矛盾，显式指出而不是静默覆盖：

> _与 ADR-0007（xxx）矛盾，但值得重开，因为……_
